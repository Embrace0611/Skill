# 数据库变更与数据迁移

从变更前后的业务语义和必须保持的数据不变量出发，先确定是否需要改写历史数据，再设计处理方式。保持独立于具体项目、语言、数据库和迁移框架。使用简体中文沟通。

职责覆盖调查、方案、实现与验证；实际运行依据当次任务的范围及已有授权。本 Skill 提供决策与实施规范，根据目标项目生成实现，优先复用已有设施。

## 1. 调查事实与约束

- 先读取目标项目的指引及已有迁移、发布、测试约定，确认数据库引擎与版本、数据模型、读写路径和部署方式。不要套用当前工作区或其他项目的约定。
- 调查旧逻辑可能造成的数据分布与异常，区分总数据量、潜在受影响量、实际需要改写量。记录来源、时间、估算方法及不确定性；不要用主键最大值代替行数。没有真实依据就标记未知，并给出调查方法。
- 对线上系统，先考虑迁移期间持续读写及新旧版本并存；有维护窗口、停写条件等证据时再简化。明确本次数据范围与持续变化的数据如何收敛。
- 方案阶段就调查可能的脏数据，确定识别、修复、隔离或暂停策略。业务含义不清的数据不能自行补成默认值。
- 沿用已有访问授权。优先使用成本可控的元数据、抽样、只读查询与隔离环境验证；全表统计和执行计划工具也需评估实际开销及是否执行语句。缺少生产访问不妨碍推进独立工作，但不得虚构调查或性能结果。

按需查阅 [策略与恢复设计](references/strategy-and-recovery.md) 中对应章节。它说明不回填、处理位置、在线兼容、批次并发、持久化恢复、异常和观测的判断依据。

## 2. 比较路线并逐项讨论

先调查能查明的问题，再询问无法从证据确定的关键分歧。每次只问一个问题，同时提供推荐答案及理由；沿着决策依赖顺序推进。

存在多条具有实质价值的可行路线时，说明适用条件、收益、成本、风险及对恢复和验收的影响，由使用者选择。被证据排除的路线注明原因，无需凑选项。已在当前任务中明确选择的事项直接沿用，不重复询问。

以下是推荐依据，不是替使用者决定的固定路线：

- 先评估默认值或兼容逻辑能否使历史数据无需物理回填；验证所有相关消费者的完整业务语义。
- 优先评估数据库内筛选、计算和批量改写；与应用或混合处理比较实际成本。数据库优先也需控制批次、事务及锁。
- 并发没有固定的单执行器或多执行器默认值。调查分片独立性、数据库余量、吞吐与恢复成本后，呈现可行路线供选择。
- 恢复能力按风险分级。短时、可原子提交且可安全重跑的迁移可复用事务和已有迁移记录；长时间、分批或可能部分完成的迁移须持久化进度并设计暂停、恢复。
- 进度必须可观察；Web 展示按需选择，优先复用已有日志、命令行、监控或管理界面。
- 脏数据可以在一致性允许且使用者选择后隔离继续；关联完整性、转换规则或影响范围不明时暂停受影响范围。提前确定策略，不能等执行失败才首次讨论。
- 每次都要有止损与恢复路径，根据实际可逆性比较回滚、补偿、向前修复或经过验证的备份恢复，说明限制。

证据唯一确定的实现细节可以先形成建议，无需逐项打断；所有未提问的选择仍须进入完整审阅。

## 3. 完整审阅，确认后才正式实现

读取并使用 [方案审阅模板](references/plan-review-template.md)。复用项目既有文档或当前对话等合适载体，不强制另建一套文档系统。

审阅内容必须覆盖所有适用考虑点，包括未提问的默认选择。逐项列明当前策略与参数、证据、备选取舍、决定来源、影响、风险和依赖。不适用项说明原因，未知项说明验证方法及是否阻塞；不能用“按最佳实践”代替选择。

**使用者明确确认当前完整方案后，才编写正式迁移 SQL、迁移程序、配套功能和测试。** 确认前可进行只读调查、说明算法及必要的隔离方案验证；不能用“先写实现供审阅”绕过关口。能安全独立推进的调查继续进行，依赖未决业务语义或安全条件的实现不得提前推进。

已有针对当前完整方案的明确确认则继续工作，不重复索要确认。沉默、仅选择某条局部路线或笼统的初始开发请求，不等于审阅了尚未展示的完整方案。

实质策略改变、范围扩大、风险增加或超出已同意的参数调整范围时，说明差异并重新确认受影响部分；已批准范围内的调优直接进行。保持最新完整方案可审阅。

## 4. 按方案实现并验证

- 适配目标项目已有迁移、任务、状态和监控设施；仅在现有机制不足时增加必要实体。不因使用本 Skill 自动创建通用调度平台、状态表或 Web 页面。
- 保证分批边界、改写和检查点具有正确恢复语义；处理重复执行、中断、业务并发写入和重复启动。多执行器路线额外落实分片所有权及失效执行器保护。详见参考文件的“分批与并发”和“持久化、暂停与恢复”。
- 明确阶段依赖、停止条件、有限重试、异常补处理及收敛校验。未知异常按预先确定的兜底策略处理，不擅自跳过、猜测修复或宣告成功。
- 按风险执行有意义的验证，覆盖适用的空数据、已迁移数据、脏数据、批次边界、中断恢复、重复执行和并发写入。涉及数据库行为时尽量使用目标引擎与版本；未验证的行为如实列为限制或运行前置条件。
- 最终完成依据是业务不变量、覆盖范围、异常处理和阶段验收。进度达到 100%、SQL 无报错或处理计数符合预期，均不能单独证明完成。

方案确认只覆盖已说明的实现范围，不自动授权改写未授权环境。若任务只要求实现，交付实现与运行说明；已明确授权的执行和验证继续完成，按既定停止条件处理阻塞。

## 5. 交付与状态说明

交付调查与规模结论、最新完整决策记录、实现产物、验证结果及运行说明。说明启动、观察、暂停、恢复、异常补处理、止损方式和剩余事项；对于不适用项简要注明。

分别说明“方案已确认”“实现已完成”“测试已通过”“目标环境已迁移并验收”等实际达到的状态。不把未运行、仅部分处理或存在未解决阻塞的任务表述为迁移成功。
