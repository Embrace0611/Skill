# 策略与恢复设计

按任务涉及的决策阅读对应章节。这里提供判断条件与正确性约束；具体路线、参数及不适用项仍需进入方案审阅。基于目标引擎、版本和配置核实数据库行为，必要时查阅其官方资料，不把某一数据库的 DDL、默认值、事务或锁行为推广到其他数据库。

## 1. 数据语义与规模

先写清变更前后语义、可信数据来源及必须保持的不变量，再调查数据，而非从线程数或迁移工具开始。

- 追踪旧代码的写入条件、版本、时间段、过滤逻辑和绕行入口；检查漏写、重复、空值、非法枚举、缺失关联及历史规则变化。旧逻辑造成的潜在影响范围与当前符合改写条件的集合可能不同。
- 分别估计总量、潜在受影响量、实际改写量，并说明数量之间的关系。调查分布、热点、偏斜、记录大小及关联放大效应，不能仅报一个总行数。
- 记录证据来源、采集时间、查询或抽样方法、上下界与未知项。样本有偏或样本不足时说明限制；未知数量不要伪造精度或统计置信度。没有生产证据时可列不同规模情景，明确它们是假设。
- 精确计数、全量校验及执行计划工具也可能有成本；先评估成本和语句是否真的执行。大范围的调查同样需要适当边界。
- 性能估计结合试跑吞吐、事务与日志成本、限速、并发业务负载、复制或下游处理能力给出范围，不把理想吞吐线性外推成承诺。

## 2. 是否回填与处理位置

### 历史数据策略

比较不回填兼容、主动回填及在适用时按需回填等路线。允许不回填成为最终方案，也允许它仅是过渡措施，需明确二者的区别。

- 不回填需证明读取、写入、SQL 筛选、排序、聚合、唯一性及其他约束、导出、报表和外部消费者均保持约定语义。界面显示正常不足以证明等价。
- 区分“未知”“未设置”“真实为默认值”等业务含义。需要恢复真实历史事实时，必须找到可信来源；无法推断应提交业务决策。
- 区分数据库默认值、查询补值、应用兼容和实际存储。不要假设定义默认值就能让所有历史数据及所有访问路径满足要求，按目标引擎与消费者验证。
- 如采用按需回填，说明首次访问延迟、并发重复处理、从不访问的数据、写入竞争及验收口径。不要把“可能以后会被访问”当作全部处理的保证。
- 临时兼容需要退出条件和清理安排；已选为最终语义的兼容方案不强制另建回填任务。

### 数据库、应用或混合处理

数据库内处理是优先评估的候选：尽量靠近数据完成过滤、关联、计算和批量改写。评估实际执行计划、索引、锁、事务及日志规模、临时空间、触发器、复制和下游影响，不能只比较网络往返或 SQL 条数。

应用处理适用于数据库难以表达、必须复用且经过核实的业务语义、外部依赖或实际成本更合适的情况。说明批量读取写入、内存界限、连接使用及外部副作用如何重试和去重；避免无依据地逐行往返或为迁移创建无上限线程。

混合路线也需有清晰边界。不得把业务服务器线程空闲误认为数据库仍有处理余量。

## 3. 在线兼容、结构变更与收敛

- 列出迁移前、迁移中、切换后各版本的读写行为。确认哪个写入方产生新格式数据，旧写入方何时退出，以及历史数据扫描后再次变化怎么办。
- 按需采用结构扩展、兼容发布、数据处理、验证、切换、清理等阶段。每阶段定义进入与退出条件、失败后的安全状态及恢复入口；简单任务可以合并或省略，但说明理由。
- 对 DDL、索引与约束变化，核实目标版本是否涉及表重写、长锁、自动提交、非事务步骤和特殊资源需求。标明哪些步骤不能按普通事务回滚、不能按行分批或不能快速暂停，并提供适合该操作的停止和恢复说明。
- 对持续变化的数据定义本次覆盖范围及最终收敛方法：可使用经验证的范围水位、版本条件、写入方切换、增量追踪或末轮对账等。扫描时的水位本身不能证明迟提交、新写入或范围内再次更新已被覆盖。
- 防止覆盖迁移期间的业务新值，按需使用条件更新、版本校验或其他适合项目的冲突规则。
- 删除旧字段、停止兼容和收紧约束，需满足所有消费者已切换及数据验收条件；不能仅因扫描结束就执行不可逆清理。

## 4. 分批与并发

### 批次边界与负载

- 优先使用稳定且唯一的键、稳定排序的复合游标或明确范围；说明被修改的键、稀疏主键、删除、过滤条件变化及最后一批如何处理。避免在变化的结果集上用偏移分页导致遗漏或重复。
- 明确每批选择、改写、事务提交、异常记录与检查点的边界。需要多次查询的批次要考虑两次查询之间数据发生变化。
- 批次大小、耗时、事务规模、锁等待、日志与复制积压、连接数及业务延迟按实际环境选择控制指标，给出参数初值的依据和允许调整范围，不预置适用于所有项目的数字。
- 参数调整遵守已确认的性能与业务影响边界。定义降速、暂停、恢复条件，避免迁移反过来拖垮服务。

### 并发路线

分别评估单执行器和多执行器。说明多执行器是否能改善真实瓶颈、能否独立分片、是否会扩大热点与锁竞争，以及任务领取、汇总、重试和恢复的额外成本。区分应用执行器并发和数据库内部并行。

多执行器必须保证分片覆盖且无遗漏，处理偏斜与失效重领。复用现有机制，按需采用任务所有权、租约或隔离措施；过期执行器不得继续提交与新所有者冲突的业务改写。仅在进度表上检查租约、却允许旧执行器继续写数据，不满足该要求。

单执行器也需考虑误启动第二个实例。保护方式与风险匹配，无需因此默认建设分布式调度系统。

## 5. 持久化、暂停与恢复

短时、可原子提交且可安全重跑的迁移可以利用项目原有事务和迁移历史。长任务、分批任务或可能部分完成的任务，恢复必须依赖持久状态，不能依赖当前进程内存或聊天记录。

优先复用已有持久化设施。根据实际需要记录迁移身份与逻辑版本、运行实例、目标与处理范围、关键参数、阶段、检查点、完成及异常统计、异常补处理信息和最近活动时间。存在多执行器时按需增加分片、所有权或租约信息，不强制统一表结构。

需要保持的恢复不变量：

- 检查点不能宣告尚未提交的工作已完成。优先让改写与对应进度在同一事务提交；做不到时设计可重放、去重、对账或等价恢复协议，说明可能发生的提交结果不确定性。
- 覆盖“数据已提交但进度未保存”“进度响应丢失”“提交成功但客户端超时”等窗口。恢复不能造成遗漏、重复副作用或重复累计成功数量，不笼统声称恰好执行一次。
- 每个已选定的工作项必须能归入已验收、明确排除、可追踪异常或待处理等状态。游标越过隔离异常时，异常必须仍有独立补处理入口。
- 恢复前校验迁移逻辑版本、处理范围及关键参数。不能把旧检查点直接交给语义或游标规则已变化的新实现。
- 区分运行、暂停请求、已暂停、阻塞、失败、待验收及完成等语义，状态名称适配项目。运行实例失联应显示失联或待判定，不能继续报告健康运行。
- 协作式暂停通常在当前有界操作安全提交或回滚后生效；说明实际暂停延迟。强制终止后，先确认事务和持久记录，再恢复。长 DDL 等不可快速暂停的步骤应单独说明。

阶段状态与细粒度进度应足以从崩溃中判断下一步。日志用于诊断；若作为恢复载体，必须具备相应持久性、一致性和可查询性。

## 6. 脏数据、阻塞与恢复路线

方案阶段为已知异常建立分类：识别条件、数量或范围、可信修复依据、受影响关联、处理路线、异常记录及补处理方法、继续与停止条件。凡是需要业务决定的含义应在实现前讨论；无法预见的异常也需预先约定兜底行为。

- 有可靠规则的异常可按已选策略修复。无法推断的数据不能自行补值或删除。
- 异常确实独立时，可以由使用者选择隔离后继续。隔离项不能计入成功；明确对完整性和后续切换的影响，以及谁或哪个步骤负责关闭异常。
- 转换规则错误、关联完整性风险或影响范围不明时，暂停相应范围；若无法证明范围独立，则扩大暂停范围。
- 临时超时、死锁或依赖故障按类型有限重试，设置退避、尝试或耗时边界，达到条件后持久化阻塞原因。业务错误和确定失败不应无限重试。
- 区分可由系统自动恢复的阻塞与需要使用者判断的阻塞；自动恢复也应在已确认的条件和次数范围内。

每个阶段明确止损方式。回滚需要可信的原始信息及可行的反向操作，并保护迁移后的业务写入；不能把反向 SQL 当作可靠证明。补偿或向前修复需定义幂等性及一致性恢复条件。备份恢复方案需考虑恢复验证、耗时、资源和备份之后的新写入，不能仅写“有备份即可”。

## 7. 进度、验收与交付

### 观察方式

所有任务应能查明实际状态，复杂度与任务匹配；短事务可依赖已有运行与结果记录。长任务至少提供适用的阶段、处理范围、扫描/匹配/改写/已满足条件/异常/待处理数量、速度、最近进展、阻塞原因及恢复入口。区分批次提交与尚未提交的计数。

说明每种计数的口径、是否重叠、是否精确及何时采集。估算总量与持续新增数据下的百分比、剩余时间需明确不确定性；验收前展示待验收状态，不把扫描 100% 等同于完成。

比较已有日志、命令行、状态查询、监控及 Web 展示。仅在选定后实现 Web，优先复用已有管理设施；区分只读展示与启停控制，控制操作也需明确选定并沿用项目权限。恢复事实应来自持久状态，不能只存在页面或浏览器会话中。

### 验证与完成标准

实现前确定业务不变量、覆盖范围、阶段验收与异常关闭标准。按风险选择完整对账、独立查询、统计约束及抽样组合；抽样结论需说明覆盖限制。不要只用迁移实现的同一段转换逻辑验证自己，也不要把所有迁移都套进简单的行数相等公式。

验证适用的故障窗口：空集合、已经满足新语义、各种已知异常、批次边界与最后一批、重复执行、提交前后中断、重复启动、并发写入冲突、失联执行器及恢复时版本不一致。数据库语义相关验证尽量使用目标引擎与版本的隔离环境。无法验证的部分记录为未验证，并说明是否阻塞运行或最终验收。

只有验收条件满足后才能报告相应阶段完成。允许明确报告部分完成及尚未关闭的异常；若使用者选择了排除范围，记录对最终交付的影响，不能把异常悄悄改为成功。

最终材料沿用项目约定：规模与证据、完整决策记录、实现与验证、运行入口、观察方式、暂停恢复、异常补处理、止损步骤和遗留事项。按事实区分代码交付、环境试跑和真实迁移验收。
