# 方案审阅模板

用于正式实现前的完整审阅。可整合进项目已有计划、迁移文档或当前对话；不要求每次额外创建文件。简化篇幅时仍需覆盖所有考虑点，不适用项写明原因。

## 1. 目标、事实与边界

说明本次变更的业务目标、变更前后语义、必须保持的不变量、目标环境、数据库引擎与版本、涉及对象及消费者、部署限制和允许的业务影响。

列出总数据量、旧逻辑潜在影响量、实际改写量及其关系；分别给出证据来源、采集时间、估算方法、分布和不确定性。没有证据的数值写未知，或明确标记为规模情景假设。

记录本次实现范围、未来运行范围及已有授权；方案确认与环境操作授权分别说明。仅在缺少必要授权时提出具体问题，不重复索要已有授权。

## 2. 完整策略审阅表

实际审阅时，针对下表每个考虑点填出以下字段：

| 考虑点 | 当前策略与关键参数 | 证据、备选路线与取舍 | 决定来源与状态 | 影响、风险与依赖 |
| --- | --- | --- | --- | --- |

决定来源与状态采用清楚的描述，例如“已讨论选择”“证据确定，待整体审阅”“未提问的建议默认值，待整体审阅”“不适用及原因”“待决及阻塞范围”。完整方案确认后记录确认的版本和范围。

有多条有价值的可行路线时应先逐项讨论再汇总；被证据排除的路线写排除依据。不强制为每个细节提供虚假的备选方案。

| 必须覆盖的考虑点 | 必须说明的选择或判断 |
| --- | --- |
| 是否真正需要历史数据改写 | 不回填、主动回填或适用时按需回填；业务语义与真实历史值的来源。 |
| 默认值及历史兼容 | 数据库存储、默认值、查询与应用兼容的分工；筛选、统计、约束和其他消费者如何保证语义。最终方案还是临时过渡。 |
| 数据规模与潜在影响 | 总量、旧逻辑影响范围、实际改写量、分布、证据和未知项；是否需要进一步精确统计。 |
| 已知脏数据 | 预调查结果、识别规则、修复或隔离路线、继续和暂停条件、异常补处理及验收。 |
| 未知异常兜底 | 遇到规则未覆盖的数据如何安全暂停、记录和补充决策；不得临时猜测修复或跳过。 |
| 在线读写与版本兼容 | 迁移期间新旧版本的读写行为、维护窗口或停写条件、冲突规则。 |
| 结构、索引和约束变化 | 引擎与版本依据、锁和表重写成本、事务限制、不可分批或不可快速暂停的步骤。 |
| 处理位置 | 数据库、应用或混合处理；业务表达能力、性能证据和副作用。 |
| 阶段与部署顺序 | 进入/退出条件、兼容发布、处理、验证、切换及清理的依赖；可省略的阶段及理由。 |
| 分批策略 | 稳定键或范围、选择与改写边界、批次大小、事务规模、最后一批及变化数据的处理。 |
| 并发路线 | 单执行器和多执行器的可行性、收益、资源与恢复代价；所选路线及依据。 |
| 分片与重复启动 | 分片覆盖、任务领取、失效重领、过期执行器保护；单执行器也考虑误启动第二实例。 |
| 性能与资源 | 执行计划、索引、锁、日志、复制或下游、连接、内存、业务延迟及相关适用指标。 |
| 参数与调整边界 | 初值依据、允许调整范围、限速、自动降速/暂停/恢复条件及何时需要重新确认策略。 |
| 持久化载体与记录 | 是否复用现有设施；迁移身份与版本、运行实例、阶段、范围、参数、检查点、统计及异常记录。 |
| 检查点一致性与重跑 | 改写与进度如何一致；提交结果不确定、重复处理和副作用如何解决；统计如何避免重复累计。 |
| 暂停、崩溃与恢复 | 风险分级、暂停生效边界、恢复入口及前置检查、版本或范围不匹配如何处理。 |
| 持续变化与最终收敛 | 本次覆盖范围，新增、迟提交和再次更新的数据如何处理，何时认定覆盖完整。 |
| 进度口径 | 阶段、扫描/匹配/改写/已满足/异常/待处理数量、速度、最近进展及阻塞；总量与剩余时间是否估算。 |
| 展示载体与 Web | 选择日志、命令行、监控、状态查询或 Web 的理由；Web 是否复用、只读还是带控制。 |
| 阻塞与重试 | 阻塞分类、重试与退避边界、暂停范围、人工处理入口及恢复条件。 |
| 止损与恢复路线 | 回滚、补偿、向前修复或备份恢复的可行性、验证与限制，如何保护业务新写入。 |
| 验收与故障验证 | 业务不变量、覆盖与对账方法、适用边界场景和故障窗口、目标引擎验证及未验证项。 |
| 完成与清理条件 | 异常如何关闭或明确排除、何时切换和清理、部分完成如何表述，长期兼容是否保留。 |
| 实现及运行交付 | 实现产物、运行入口、观察与恢复方法、执行范围及权限、最终交付状态。 |

不得遗漏未提问而默认选择的项目；在表中显式标记这些默认值及理由。若一项包含多项有独立后果的选择，拆成多行，不用一个笼统结论覆盖。

## 3. 阶段与运行约定

按所选方案说明阶段顺序。需要分阶段的任务逐阶段列出：目标、进入条件、改写范围、持久记录、退出与验收条件、失败后的安全状态及恢复入口。简单任务可合并，不强制复杂状态机。

列出运行前置条件、允许影响范围、限速和停止条件、异常记录与补处理方法、重试与恢复边界。长步骤明确实际暂停能力和延迟；不能承诺无法实现的即时暂停。

## 4. 验证计划与未决项

实现前给出适用的验证场景、预期不变量、验证方法与环境；完成实现后再补充实际结果和证据，不预填“通过”。根据风险覆盖空数据、已满足条件、脏数据、批次边界、中断、重复执行、并发写入及失效恢复等场景。

未知项逐项写明：缺少什么证据、如何验证、是否影响路线选择或安全性、阻塞哪个阶段。依赖业务含义或安全条件的未决项应在正式实现前解决；不相关的调查可继续。暂缺性能或环境证据时明确条件性结论及运行前必须完成的验证。

## 5. 方案确认关口

完成以上审阅后，以一个明确问题请求使用者确认当前完整方案，再开始正式实现。引用方案版本或清晰可识别的内容范围；若存在阻塞决策，先逐个解决并更新审阅内容。

只读调查与必要的隔离方案验证可以先做；正式迁移 SQL、迁移程序、配套功能和测试在确认后编写。已有针对当前完整方案的明确确认就直接继续。

后续发生实质变更时，更新最新完整方案并说明改变了哪些选择、原因和影响，只对受影响部分重新确认。已同意范围内的参数调节无需重复确认。确认方案不自动扩大环境操作权限。

## 6. 实现后补充

补充实际实现入口、配置参数、已验证内容与环境、未验证项、启动/观察/暂停/恢复/补处理/止损方法，以及真实达到的状态。沿用任务已有授权继续必要工作；仅当用户要求且已授权时运行目标环境迁移。

清晰区分方案已确认、实现已完成、测试已通过、目标环境已迁移并验收。仍有异常或未覆盖范围时，说明部分完成及对后续步骤的影响。
